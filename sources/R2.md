# R2 — NetworkX: Shortest Paths（來源紀錄）

## 1. 來源摘要

NetworkX 官方文件說明最短路徑問題的定義、加權與非加權圖的差異、有向與無向圖的路徑限制，以及不同最短路徑演算法的選擇。文件也區分 single-pair、single-source、all-pairs 等查詢類型，並提供典型演算法時間複雜度概觀。

- Documentation version：NetworkX 3.7
- URL：<https://networkx.org/documentation/stable/reference/algorithms/shortest_paths.html>
- 本次核對段落：Shortest Paths、Algorithms、Simplified Interface。

## 2. 本 Wiki 擷取範圍

1. 最短路徑的定義：在圖中尋找總距離／成本最小的路徑。
2. 非加權圖以邊數最少作為路徑長度；加權圖以路徑上邊權重總和作為成本。
3. 有向圖必須遵守邊的方向；無向圖的邊可沿任一方向通行。
4. 查詢範圍：single-pair、single-source、all-pairs。
5. 演算法概觀：BFS、Dijkstra、Bellman-Ford；文件亦列出 Floyd–Warshall 與 Johnson 作為 all-pairs 方法。
6. 典型時間複雜度概觀：BFS 為 \(O(V+E)\)、Dijkstra 為 \(O((V+E)\log V)\)、Bellman-Ford 為 \(O(VE)\)。本 Wiki 將其視為常見實作的概觀，細節與前提留待 Time Complexity 頁面補充。

## 4. 重要限制與避免誤解

- 不可將「最短」一律解釋成邊數最少；在加權圖中應比較總權重。
- Dijkstra 的適用條件是邊權重非負，不可寫成適用於所有加權圖。
- Bellman-Ford 能處理負權重邊，但若存在從來源可達、並能影響所求路徑的負權重環，受影響目的地可能不存在有限最短距離。負環細節留待 Bellman-Ford 頁面說明。
- NetworkX 文件中的複雜度表屬於典型演算法概觀；Time Complexity 頁面仍需說明圖表示法、優先佇列實作及分析前提。
- NetworkX 的 `weight` 參數、缺少指定 edge attribute 時預設權重為 1 等內容，是特定 API 行為，不應寫成最短路徑問題的一般數學定義，因此沒有納入主頁正文。
