02 / GRAPH BASICS

先認識 Graph：節點與連線

03 / 14

Graph（圖）用來描述物件之間的連結關係，由頂點集合與邊集合組成。

Vertex = 頂點Edge = 邊Neighbor = 鄰點
1

Vertex（頂點）

代表一個物件，例如城市、路口或使用者。

2

Edge（邊）

代表兩個頂點之間存在連結。

3

Directed / Undirected

有向邊只能依箭頭前進；無向邊可雙向通行。

可以把城市想成 Vertex，把道路想成 Edge。只要把連接關係畫出來，就能形成一張 Graph。

03 / SHORTEST PATH

「最短」不一定代表邊數最少

04 / 14

Weighted Graph（加權圖）的每條邊有成本。最短路徑要比較的是路徑總權重，而不只是經過幾條邊。

路線 A

經過 3 條邊

A→B→D→F
4 + 10 + 11 = 25

邊數比較少，但總成本較高。

路線 B

經過 4 條邊

A→C→E→D→F
2 + 3 + 4 + 11 = 20

邊數更多，但總成本更低。

最短路徑的核心：先定義要最小化的成本，再比較所有符合連線方向的可行路徑。
知識依據：Wiki 03 Shortest Path ProblemR1、R2 · NETWORKX
04 / ALGORITHM SELECTION

先看邊的權重，再選演算法

05 / 14

BFS、Dijkstra、Bellman-Ford 都能處理單源最短路徑的不同情境，但適用條件不同。

非加權／等成本邊

BFS

用 FIFO Queue 逐層探索，找出經過邊數最少的路徑。

O(V + E)

鄰接串列實作

所有權重 ≥ 0

Dijkstra

每輪確定目前暫定距離最小的頂點，並更新鄰點。

O((V+E) log V)

鄰接串列 + Binary Min Heap

允許負權重邊

Bellman-Ford

反覆掃描所有邊並鬆弛，額外檢查來源點可達的負環。

O(VE)

最多 V−1 輪邊掃描

本簡報的主角是 Dijkstra：適用於邊權重全部非負（可以是 0）的加權圖。
知識依據：Wiki 03、07、10R2、R3、R5
05 / DIJKSTRA'S IDEA

Dijkstra：每次先確定最近的候選點

06 / 14

從來源點出發，反覆挑出目前距離最小、但還沒確定最短距離的頂點。

01 · 選擇

Greedy Strategy

從 Frontier 中選出 `dist` 最小的頂點。

02 · 確定

Settled

將該頂點標記為已確定；它的最短距離不再改變。

03 · 更新

Relaxation

檢查外連邊，找到更短候選時更新距離與前驅。

為什麼可以放心確定？因為所有邊權重皆非負，後續路徑再增加邊，不會讓總成本下降。這是 Dijkstra 正確性的重要依據。
Undiscovered：尚未發現Frontier：候選中Settled：距離已確定
知識依據：Wiki 04 Dijkstra AlgorithmR3 · CORNELL CS 2110
06 / ALGORITHM STATE

Dijkstra 會記錄哪些資訊？

07 / 14

演算法需要記住「目前距離多少」、「路徑從哪裡來」，以及「哪些頂點已經確定」。

dist[v]｜距離估計

目前找到的來源點到 v 的最佳候選距離。還沒找到路徑時是 ∞。

prev[v]｜前驅頂點

記錄目前最佳路徑中，v 的前一個頂點；最後可用來還原路徑。

settled｜已確定集合

存放最短距離已確定的頂點，之後不再更新它們。

PQ｜最小優先佇列

依暫定距離由小到大取出 Frontier 頂點，快速選下一個處理對象。

INITIALIZATION

起點距離設為 0；其他頂點先設為無限大。

dist[s] = 0  |  dist[v ≠ s] = ∞

09 / EDGE RELAXATION

Edge Relaxation：發現更短，就更新

10 / 14

鬆弛（Relaxation）就是檢查：經過某條邊的新路徑，是否比目前記錄的路徑更便宜？

CANDIDATE DISTANCE
candidate = dist[u] + w(u,v)
ONLY UPDATE WHEN
candidate < dist[v]
  • 更新 `dist[v] = candidate`
  • 更新 `prev[v] = u`
  • Dijkstra 中同步更新 PQ 優先權
EXAMPLE

找到更便宜的到 B 路徑

A—7→B

目前 `dist[B] = 7`

A—2→C—3→B

新候選距離：2 + 3 = 5

5 < 7 → 更新為 5

因此 `prev[B] = C`。

Dijkstra 與 Bellman-Ford 都使用 Relaxation；差異在於它們安排鬆弛操作的方式：Dijkstra 依距離選頂點，Bellman-Ford 反覆掃描所有邊。
知識依據：Wiki 05 Edge RelaxationR3、R5
10 / PRIORITY QUEUE & COMPLEXITY

為什麼 Dijkstra 需要 Min-Priority Queue？

11 / 14

每輪都要快速找出 Frontier 中距離最小的頂點；Min Heap 能讓這個選擇有效率。

Indexed Min Heap 操作

Peek-MinO(1)
InsertO(log V)
Extract-MinO(log V)
Decrease-KeyO(log V)

Decrease-Key 假設額外維護「頂點 → Heap 索引」對應；一般未索引的 Binary Heap 不一定能直接定位指定頂點。

三種演算法的典型時間成本

BFSO(V + E)

鄰接串列 + FIFO Queue

DijkstraO((V+E) log V)

鄰接串列 + Indexed Binary Min Heap

Bellman-FordO(VE)

最多 V−1 輪掃描所有邊，再做負環檢查

複雜度分析前提：Dijkstra 使用鄰接串列與支援 decrease-key 的 Binary Min Heap。輔助空間 O(V) 不包含圖本身的儲存空間；更換圖表示法或佇列實作，複雜度也會改變。
知識依據：Wiki 06 Priority Queue、07 Time ComplexityR1–R5
11 / ALTERNATIVES

另外兩種方法：BFS 與 Bellman-Ford

12 / 14
BFS · 廣度優先搜尋

一層一層向外找

  • 使用 FIFO Queue。
  • 先找距離 1 條邊的頂點，再找 2 條邊、3 條邊。
  • 適合非加權圖，或每條邊成本相同且非負。
  • 不能保證不同權重下的最低總成本路徑。
O(V + E)
Bellman-Ford · 貝爾曼－福特

反覆鬆弛所有邊

  • 最多執行 V−1 輪，每輪掃描所有邊。
  • 可處理負權重邊。
  • 額外掃描一次，檢查來源點可達的負權重環。
  • 受可達負環影響的頂點沒有有限最短距離。
O(VE)

快速記憶

BFS：邊數最少Dijkstra：非負權重、總成本最低Bellman-Ford：允許負權重並偵測負環

12 / CHECK YOUR UNDERSTANDING

重點整理：你會選對演算法了嗎？

13 / 14

四個重點先帶走

1

最短路徑的「短」取決於成本定義：可能是邊數，也可能是權重總和。

2

Dijkstra 要求所有邊權重非負；每輪確定 Frontier 中距離最小的頂點。

3

Relaxation 用候選距離改善 `dist`，並用 `prev` 記錄路徑。

4

Priority Queue 協助選最小距離；BFS 與 Bellman-Ford 有不同適用條件。
